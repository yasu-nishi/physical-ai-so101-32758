# 画像を確認しながらPythonを1段階ずつ生成する

> 既知高さ版・旧試行の記録。現在の未知高さ計測と段階XYZ生成は[STAGED.md](STAGED.md)、追加結果は[STAGED_RESULTS.md](STAGED_RESULTS.md)を参照。以下の未実装・未検証の記述は、この旧試行時点の範囲を示す。

`observe → AIが次の小動作を選ぶ → prepare_step → Pythonを実行 → 新しいRGB → 次の判断`。
一連の搬送軌道を最初に確定する必要はない。今回追加した方式は、1回の関節相対移動だけを生成し、その後は止まって次の判断を待つ。

AIは画像の根拠、動かす関節と量、予想する見え方を指定する。ローカル処理が制限を検査し、軌道JSONと実行用Pythonを雛形から生成する。生成PythonはMCPの`prepared_step`を1回実行し、完了後の画像を保存して終了する。AIがPython本文を自由に合成したり、サーバーが任意のPythonを実行したりする方式ではない。

## 1回の操作

通常のsim/realサーバーを起動し、`observe`のRGBを実際に表示する。次の数値は呼出し形式の例であり、固定ポリシーとして連続実行しない。

```sh
uv run --locked python scripts/mcp_call.py prepare_step --args '{"observation_id":"NEW_OBS_ID","joint_delta_deg":{"shoulder_pan":-1.0},"gripper_delta":0.0,"instruction":"元の作業指示","visual_reason":"最新の画像で確認した根拠","expected_visual_change":"次の画像で確認したい変化"}'
# 返されたprogram_idの実ファイルを実行する。
uv run --locked python artifacts/MY_RUN/programs/PROGRAM_ID.py
```

実行後の`PROGRAM_ID_after.png`をAIが表示し、前の画像と比較する。`_execution.json`の新しい観測IDを次の生成に使う。予想と逆なら方向や量を修正し、不明瞭なら停止する。物体をつかんだ、箱に入った、という主張はその証拠が画像にあるときだけ記録する。

既定値は各関節±2度、全関節の絶対変更量の合計4度以下、グリッパー開度±0.1、1回0.6〜3秒。腕とグリッパーを同時に変更せず、その間も再観測する。速度、絶対関節範囲、実行時間、追従誤差、ローカル停止は既存制御側で検査する。

同じ画像から複数の次動作を生成しても、最初の動作後は残りが失効する。新しい画像なしでの連続実行を拒否する。同じrequest_idの通信再送では再実行しない。停止はMCP `stop`、ローカルSTOPファイル、操作者のCtrl-Cで行う。

## 高さとの関係

この関節相対APIは深度、物体座標、カメラ外部校正、実機の逆運動学を入力に要求しない。画像の変化から次の小動作を選べる。ただし「2度動かす」は「手先を2mm下げる」という意味ではなく、物体との距離や接触も保証しない。

画像に見えるずれを直すことと、未知の高さを測ることは別に評価する。単一の固定視点で高さや指と物体の接触が曖昧な場合に、下げ続けるループは実装していない。未知高さの把持完遂には、横からの観測、複数視点、既知形状、接触を確認できる計測など、実際の環境で使える手掛かりと検証が必要。

## 実機

同じ`prepare_step`をrealでも使える。標準はドライランで、実測関節と画像を返し、目標値をモーターへ書かない。実機用アダプターを使った模擬テストで書込み0と実測値不変を確認した。現物試験はUSB未接続のため未実施。

実際に動かす前に、READMEの正方向・ゼロ点・可動範囲・停止の現物照合と、カメラで安全な作業域を観測できることを確認する。既存の手動操作で小さい正負方向の動きを確認し、ローカル設定の`mapping_verified`、`workspace_verified`、`camera_role`と`incremental_steps.real_motion_verified`を操作者が設定する。その後、端末の`--enable-motion`と`ARM`で起動する。AIからこれらの設定を変更する機能はない。

関節相対方式だけを使う場合は教示済み搬送ファイルを必須にしない。固定置き場の`pick_place`には引き続き教示ファイルが必要。小さい関節増分でも衝突しないことを保証する処理はなく、実機の自由配置把持が完成したとは扱わない。

## 実際の検証

`incremental_01`ではこのCodexが各RGBを表示してから次を生成した。

| 段階 | 生成した変更 | 再撮影で確認したこと |
|---|---|---|
| 1 | shoulder_pan +2度 | 右へ動く予想に反して指先が左へ動いた。次の方向を修正 |
| 2 | shoulder_pan -2度 | 指先が右へ戻った。次は同方向へ量を小さくする判断 |
| 3 | shoulder_pan -1度 | 指先がさらに少し右へ動いた。ここで停止 |

各0.6秒、合計1.8秒の物理動作。3つの生成Pythonを実行し、指令は3/3完了。最初の方向予想は1回誤ったことも記録した。把持・搬送・高さ測定は行っておらず、搬送成功数へ加算しない。深度・sim専用手先姿勢・物体の内部座標は判断に使用していない。

元画像・生成Python・計画JSON・各回の実行結果・原動画は`artifacts/runs/incremental_01/`。集計は`scripts/summarize_incremental.py`と`artifacts/incremental_experiments.json`。56件の自動テストには、新観測の要求、先に生成した次動作の失効、増分/絶対範囲、停止、実機ドライランも含む。
