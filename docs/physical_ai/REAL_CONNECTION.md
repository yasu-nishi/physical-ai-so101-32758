# 実機接続の確認記録

2026-11-01、SO-101実機から5関節の度数・グリッパー開度と机上のRGB画像を読み、共通MCPの`observe`でPNGコンテンツとして取得した。以下の表は、モーターへ書き込まなかった初回の接続試験を記録する。その後に行った初期姿勢の自動調整は、追従監視と電圧監視で停止した。現在の書込み回数と失敗内容は[初期姿勢調整の記録](COMMISSIONING.md)に分ける。simの設定、物体配置、動作は変更していない。

## 確認できたこと

| 項目 | 結果 |
|---|---|
| USBシリアル | 認識。モーター用電源の投入後、6モーターと通信成功 |
| 既存校正 | 最初のrobot IDは不一致。別の保存済み校正が本体の6モーター・全30項目と一致し、そちらを再利用 |
| 関節・開度 | LeRobotの実測値を取得。角度はdegree、グリッパーは0–1で別扱い |
| カメラ | 外付け2台を撮影確認。index 0は現姿勢で天井、index 1は机と腕を撮影。MCPではindex 1、640×360を使用 |
| MCP | 11ツールを列挙。`observe`の実画像と関節値、`get_status`の`real` / `dry_run` / 接続済みを確認 |
| 未校正の操作 | 高さ計測と手先座標の動作生成を拒否。値を推測で埋めない |
| 現在姿勢の制限 | 折り畳んだ姿勢の肩・肘が設定済み運用範囲外。微小な関節動作の準備も拒否 |
| 停止 | MCP停止とローカルSTOPを別セッションで確認。停止後も新画像を取得でき、新しい動作生成は拒否 |
| 実機動作 | 未実施。位置目標・校正・トルク設定の書込みなし。把持・搬送成功の証拠ではない |

MCP停止は約54ms、ローカルCLIから停止確認までは約69msだった。これは各1回、待機中のソフトウェアラッチの応答時間であり、動くモーターが止まるまでの時間ではない。測定値と検証範囲は[公開用集計](../../artifacts/real_connection_verification.json)に記録する。画像・元ログ・校正照合・固有IDはローカルの`.local`ディレクトリへ保存し、公開しない。

実カメラから5秒・50フレームの観測映像も取得した。撮影前後でモーターの目標位置・トルクレジスターが変わらないことを読み取り確認した。映像は動作実験ではなく、ローカル確認用として公開パッケージから除外する。

高さ検査後の読取り基準記録では、保存済み6モーター校正と一致し、6個すべて保持トルク0だった。折り畳み状態の肩・肘は設定済み運用範囲外だった。この時点の証拠ハッシュが公開集計の`latest_registration_baseline`にある。その後、操作者から自動調整の指示を受け、別のローカル初期調整処理を実行した。現在は腕5関節の保持が有効、グリッパーは無効。初回の読取り記録のゼロ書込みを、現在の状態として扱わない。

## この作業環境で再開する

検出した既存校正と机上カメラの選択は、`config/physical_ai/real_staged.local.json`と`.env`の`SO101_MCP_FOLLOWER_ID` / `SO101_MCP_CAMERA_INDEX`へ保存した。従来のテレオペレーション用変数は変更していない。これらのローカルファイルは公開用パッケージには入らない。

```sh
# 毎回、新しい出力先を指定する。動作は有効にならない。
uv run --locked python scripts/real_check.py \
  --config config/physical_ai/real_staged.local.json \
  --output artifacts/real_check_next.local
uv run --locked python -m so101_mcp serve --backend real \
  --config config/physical_ai/real_staged.local.json \
  --transport streamable-http --port 8766 \
  --run-dir artifacts/real_next.local
```

別端末から観測とローカル停止を行う。

```sh
uv run --locked python scripts/mcp_call.py observe \
  --url http://127.0.0.1:8766/mcp --output artifacts/real_client_next.local
uv run --locked python -m so101_mcp stop --run-dir artifacts/real_next.local
```

他の環境では`real_staged.json`をコピーして自分の既存robot IDと作業台カメラを指定する。今回のカメラindexは接続順に依存するため、USBをつなぎ直したら実画像で再確認する。校正が不一致でも、直ちにモーターへ校正を書き戻さず、既存のrobot IDとの対応を先に確認する。

最初の撮影はmacOSの許可待ちで失敗し、許可確認後の再試行で成功した。必要な場合は[Appleのカメラ権限の手順](https://support.apple.com/guide/mac-help/control-access-to-your-camera-mchlf6d108da/mac)で実行元アプリの許可を確認する。権限の自動変更は行わない。

## 動作の前に残る現物作業

1. 初期姿勢調整で生じた停止原因と電源条件を確認する。停止中の保持を勝手に解除したり、運用範囲・追従条件を緩めて続行しない。手動で姿勢を変える場合も、操作者が腕を支持してトルク状態を確認する。
2. 赤・青のブロックと箱を作業範囲へ置き、カメラ1を固定する。現在の画像からはこのタスク用の2ブロックと箱は確認できていない。
3. [RGB校正](RGB_REAL.md)と[関節・手先の対応](STAGED.md)を実物の測定値で確認する。カメラをsimに合わせる必要はないが、実機の校正をsimからコピーしない。
4. 確認済みの値だけローカル設定へ反映し、操作者が`--enable-motion`と端末での`ARM`を明示してから、短い空荷動作、把持、搬送へ進む。

全動作フラグは未検証のまま。保存済みサーボ校正との一致は、ロボットモデルのゼロ点・正方向・手先座標が実物と一致することを保証しない。
