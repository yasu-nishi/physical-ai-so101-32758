2回目の電圧異常を起こした瞬間の値は保存できていなかった。後から取得した4.5–4.9Vを、その異常値の代わりに扱わない。現在のコードは停止時の電圧・電流・温度・負荷を保持するよう修正し、監視値が正常へ戻っても原因標本を失わないテストを追加した。実行時ソースの自動保存も追加したが、この2試行の実行ソース全体は保存されていない。書込み履歴・画像・レジスター診断・映像は残っている。

集計は[公開用JSON](../../artifacts/real_commissioning_verification.json)。初回の読取り専用MCP接続は[別の記録](../../artifacts/real_connection_verification.json)であり、そのゼロ書込み回数と今回の書込みを混同しない。sim、実機校正ファイル、MCP用の検証フラグは変更していない。机座標、モデルの正方向・ゼロ点、接触の安全性、把持搬送の成功は未検証のまま。

## 初期調整のコード

`scripts/commission_joints.py`はローカル専用の初期調整。MCPから呼ぶ機能はない。デフォルトは読取りのみ。既存の6サーボ校正が本体と一致し、カメラが更新され、位置モード・速度単位・電源・温度・負荷・現在角が開始条件を満たす場合だけ、明示的な`--execute`で保持を有効にする。現在値を目標として設定・読戻ししてからトルクを有効化し、目標0のまま始動しない。グリッパーへは一切書き込まない。

腕を折り畳んだ状態が通常タスクの運用範囲外の場合、初期超過が5度以下の関節だけを扱い、指令は超過を厳密に減らす方向に限定する。物理エンコーダ校正範囲は常に守る。肩・肘・手首ピッチだけを1回0.2–1.5度で動かし、起点からの変化と合計動作量にも上限を設ける。pan、roll、グリッパー、Cartesian座標、保存済み待機姿勢は指令できない。これで衝突回避を保証するものではなく、操作者同席で毎回画像を確認する初期調整に限る。

カメラは既存の`calibrate_rgb_live.py`の127.0.0.1:8770を利用する。同じカメラを二重に開かない。

```sh
# 読取りのみ。既に保持中の腕への通常の接続は拒否する。
uv run --locked python scripts/commission_joints.py \
  --config config/physical_ai/real_staged.local.json \
  --run-dir artifacts/commission_check.local

# 明示的な操作者の指示をauthorization.local.jsonのuser_instructionへ記録し、
# 開始条件と停止原因を解決した後にだけ実行。現在の停止試行を自動再開しない。
uv run --locked python scripts/commission_joints.py \
  --config config/physical_ai/real_staged.local.json \
  --run-dir artifacts/commission_new.local \
  --execute --authorization-note config/physical_ai/authorization.local.json
```

起動しただけでは関節を移動せず、保持する。確認した1動作だけを`commands`内のJSONへatomic renameで渡す。形式は`{"joint":"elbow_flex","delta_deg":-1.5}`。毎回、`status.json`の完了・実測値と新しいカメラ画像を確認する。失敗・停止を無視して次を投入しない。

停止は http://127.0.0.1:8771/ のボタン、Ctrl-C／SIGTERM、または以下で行う。ブラウザーからは停止と状態取得だけができ、通電や動作開始はできない。

```sh
uv run --locked python -m so101_mcp stop --run-dir artifacts/commission_new.local
```

停止はラッチし、保持を続ける。電源を切ると保持力がなくなる。通信断では保持指令が届かない場合がある。`EXIT`ファイルでプロセスを終了しても、意図せず腕が落ちないよう保持トルクは解除しない。終了後はソフトウェア監視がなくなるため、操作者へ状態を引き継ぐ。

停止済みの保持を引き継ぐ`--adopt-stopped-run`は、前プロセスが終了し、STOP/EXIT記録、保持トルク、目標と実測値の一致を確認できる1回の明示的な引継ぎだけに限定する。元の起点・動作量上限を引き継ぎ、トルクを切らない。今回の2回目の起動はこの手順で行った。現在の停止からの連続した再試行は許可しない。

## 記録と検証

`events.jsonl`は全レジスター書込みの試行とACKを区別する。`status.json`はラッチ後も読取り監視で更新する。最新版は`executed_source`へソースとローカル設定を保存し、停止原因の標本も保存する。これらは私用の`.local`へ置く。

`scripts/record_local_preview.py --run-dir artifacts/recording.local`で既存カメラ配信を5 fpsで録画する。同ディレクトリに`RECORD_STOP`を置くと終了する。最長10分、各フレームの時刻と元画像の更新番号を保存する。実画像は公開用exportの対象外。

最初の初期調整・停止テスト28件と既存実機アダプター2件が成功し、その時点の全体は111件成功した。追加の通信診断と応答フラグ検査を含む最新版は、初期調整31件・通信診断19件を含め全体133件成功。最新版CLIはSDKが捨てていたサーボ応答エラーも検出して停止し、保持目標・トルク・位置の確認に失敗した場合は保持未確認を表示する。この修正後の実機動作は未実施。ハードウェアを模したテストは実機の動作成功を意味しない。再開には電源条件と実測値の異常を切り分け、短い動作の実測完了を確認する必要がある。
