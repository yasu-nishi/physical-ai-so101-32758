# 関節・グリッパーの表現と校正

共通状態は `joints_deg`（下表の5つの名前を持つ辞書、単位は度）と `gripper_open`（無次元0〜1）。関節の位置は絶対目標。配列を組み立てる箇所の順序は下表に固定し、MuJoCoの自由関節や内部添字には依存しない。グリッパーを第6の角度としてAIへ提示しない。

段階XYZ版は[STAGED.md](STAGED.md)のrobot-only FK/IKを追加。`model_offset_deg`は共通角からMJCF角への差、`model_to_work`はモデルから実測作業座標への剛体変換。LeRobot用mapping offsetとの二重補正を避ける。実機の基準点はMJCFのgripperframeに対応させ、独立したXYZ・軸の実測で確認する。初期値は未検証。

把持中に腕を動かすときは、接触で開いている実測開度ではなく直前の閉指令を維持する。実測開度を次の目標へコピーして把持力を失う問題を開発試行で修正し、接触物理の回帰試験を追加した。実機での把持力・摩擦・滑りは未検証。

## sim

名前 `robot/<joint>` からqpos/actuatorの添字を取得する。5関節は `radians = degrees × π / 180`、ゼロはMenagerie MJCFのゼロ姿勢、正方向は各関節のローカル+Z軸周りの右手系。ローカル座標軸は親bodyのquatで世界座標へ変換されるため、正値を世界の同じ方向とは解釈しない。

グリッパーは `q = -0.174533 + g × (1.7453292 + 0.174533)`（ラジアン）。これは可動角範囲の正規化であり、指先間距離[mm]に比例しない。検証済み動作では開く指令g=0.611768（約1.0 rad）、閉じる指令g=0.03882（約-0.10 rad）。把持中は物体との接触により実測値が閉指令まで届かない。これを関節追従エラーに含めない。

## real

LeRobot **v0.5.1 / 1396b9fab7aecddd10006c33c47a487ffdcb54b4** の `SOFollowerRobotConfig(use_degrees=True)` を明示する。この版の腕の度数は、校正済みエンコーダ値val、校正範囲min/maxに対し `(val - (min+max)/2) × 360 / 4095`。ゼロは校正範囲の中点であり、MJCFゼロとの物理的一致は保証されない。Homing_Offsetは既存校正とモーター側の処理に任せ、二重に足さない。正のLeRobot値はこの校正済みエンコーダ値の増加方向。

設定は `motor_deg = sign × common_deg + offset_deg`、逆変換は `(motor_deg-offset_deg)/sign`。現在のreal設定のsign=+1 / offset=0は既存LeRobot座標をそのまま表す初期値であり、実機での正方向・ゼロ一致は **未検証**。`mapping_verified=false` とし、動作開始を拒否する。実機の動作点は実機で別に登録するため、simの角度列をそのまま実機に送らない。

LeRobotのgripperは `MotorNormMode.RANGE_0_100`。`motor_gripper = closed + g × (open-closed)`、初期値はclosed=0/open=100。閉・開端点の物理確認後に設定を更新する。腕の度数やモーターの内部角度と混ぜない。

realの運用制限は設定ファイルで個別指定。接続時に、現在の校正範囲から換算した角度限界と運用制限を照合する。現在姿勢、全経由点、補間中の指令と実測を検査し、範囲外・NaN・追従失敗は停止する。グリッパー端点とsign/offsetの往復変換、境界拒否は自動テスト済み。物理的対応は実機でのみ確認できる。

## 実機で確認する最小手順

1. followerのUSB、電源、使用カメラを接続。正しいrobot IDと対応する既存校正を指定する。
2. `scripts/real_check.py` で位置・画像を取得する。既存の待機姿勢の単位は `degrees_except_gripper_0_100` であることを確認済み。現在の校正IDと一致するかを現物で確認してから利用する。
3. 腕を支持した状態で各関節を小さく手で動かし、読み値の増減とローカル正方向を比較する。基準姿勢からoffsetを決め、開閉端点を確認する。既存校正の書換えが必要なら元リポジトリの `make calibrate-follower`、またはLeRobotの公式校正CLIを操作者が実行する。
4. 実機専用の観測姿勢・把持・搬送経由点を登録。テーブル、箱、ブロック位置を固定する。手首カメラのみなら、観測姿勢で両置き場と箱が写ることを確認する。写らなければ外部カメラを追加する。
5. 実測対応が確認できた設定だけ `mapping_verified` と `workspace_verified` をtrueにし、`camera_role` を `overhead` / `front` / `wrist` などへ変更。ドライランの軌道を確認した後、ローカル端末でARMして低速から検証する。
