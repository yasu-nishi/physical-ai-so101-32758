# AI作業手順（sim / real共通）

判断役は画像入力とMCPに対応するChatGPT / Codex。Astraを第一候補としてクライアント側で選ぶ。サーバーはモデルを指定・呼び出ししない。本実験の判断役は作業中のCodexセッションであり、モデルの厳密な識別子は未記録。Astra固有の性能検証とは扱わない。

以下をMCP接続後の会話に渡す。

現在の未知高さ・XYZ段階生成版（sim_staged.json / 校正済みreal_staged.local.json）は次を使う。詳細は[STAGED.md](STAGED.md)。

```text
observeのRGBを実際に表示し、指示の対象と支持面を選んでください。
未知高さの直立ブロックは、同じ可視垂直辺の上下端をmeasure_heightへ指定します。
上面中央が見えなければcenter_pixel=nullとし、中心を作り話で補いません。
机面Z=0や測定済みの台面だけを支持面に使い、物体寸法は入力しません。
高さ区間と対応する辺を確認し、近い高さを区別できなければ保留してください。
prepare_cartesian_stepへ、次のXYZまたは開度のどちらか1つ、観測ID、元指示、画像の根拠、予想変化を渡してください。
返るプレビューと制限を確認して1段分の生成Pythonを実行します。
動作後の新しいPNGを必ず表示し、予想と比較してから次の1段を生成してください。
把持後は短い試験持上げで保持を確認し、確認なしで搬送を続けません。
位置ずれ・滑り・落下が起きたら失敗を記録し、見える新しい位置・姿勢・高さから再判断します。
見えない下端、傾いた辺、未校正のカメラから高さを確定しないでください。
内部物体ID、正解位置、評価ファイル、seed、仮想深度は判断に使いません。
指令完了とタスク成功を分け、解放・退避後の画像でreport_resultを記録します。
realは標準dry_runで、現物検証フラグやARMをAIから有効化しないでください。
```

以下は関節小動作の旧手順。各動作後に判断をやり直す点は共通。詳細は[INCREMENTAL.md](INCREMENTAL.md)。

```text
observeのRGBを実際に見て、次の小さな動作だけを選んでください。
prepare_stepへ観測ID、関節ごとの差分（度）または開度差分、元の指示、画像上の根拠、予想する変化を渡してください。
生成した1回分のPythonまたはprepared_stepを実行し、完了後に返る新しい画像を表示してください。
予想と実際を比べてから、次を生成する・量/方向を修正する・停止する、のいずれかを選んでください。
未来の判断をまとめて生成しないでください。古い画像からの次動作は失効します。
関節角の変更を手先のmm移動と同一視せず、深度・高さ・接触を推測だけで確定しないでください。
画像で判断できない状況では停止し、下降を繰り返さないでください。
指令完了と把持/搬送成功を区別し、realのdry_runを物理動作の成功としないでください。
```

連続XY・生成スクリプト版（`sim_continuous.json`）は次の手順を使う。

```text
「赤いブロックを箱に入れて」を実行してください。
get_statusでsimかつsimulationであること、observeでcontinuous_image_pick=trueを確認してください。
実際のPNGを見て、指定色のブロックの上面中心を元画像のピクセル(u,v)で選んでください。
通常構成はRGBと関節・開度を使い、depth_sampling=false、手先姿勢available=falseです。
prepare_pickは既知の直立30mmブロック用です。高さを測ったとは主張しないでください。
位置だけ確認する場合はlocate_on_planeへ既知のplane_z_m=0.03を明示します。height_measured=falseが返ります。
未知の高さ・寸法ならこの方法では位置を確定できません。深度診断や評価ファイルで補わないでください。
対象が隠れる、形状・高さが違う、既に箱内の場合は動かさないでください。
prepare_pickに観測ID、ピクセル、元の指示、見えた根拠を渡してください。
返ったプレビューの黄色い印が上面中心にあること、生成された位置と軌道を確認してください。
返されたPythonファイルを実行するか、execute_skillのprepared_pickを同じprogram_id・観測ID・指示で呼んでください。
完了後に新しいPNGを実際に表示し、report_resultに成功・失敗・不明と見えた根拠を記録します。
指令完了をタスク成功とは扱いません。評価ファイル、seed、物体の内部位置は選択に使いません。
```

固定置き場版と実機の教示動作は次の手順を使う。

```text
SO-101で「赤いブロックを箱に入れて」を実行してください。
最初にget_statusでbackendとmodeを確認してください。
observeの画像コンテンツを実際に見て、色とslot_a / slot_bのラベルから対象の置き場を選んでください。
画像で対象が見えない、ラベルが曖昧、既に箱内にある場合は推測して移動しないでください。
固定の色・置き場対応、シミュレータ内部状態、評価ファイル、seedを選択に使わないでください。
execute_skill(name="pick_place", args={"slot":選んだ置き場,"destination":"box"},
 observation_id=画像のID, instruction=元の指示, request_id=この試行の一意なID)を1回呼んでください。
get_statusで完了・失敗・停止を確認します。実行中の画像取得は行わず、完了後にobserveを再度呼びます。
再撮影画像で対象が箱内にあるか、元の置き場が空か、他のブロックが残っているか、指が退避したかを判断します。
report_resultにaction_id、最後のobservation_id、success / failure / uncertainと見えた根拠を記録してください。
指令完了だけで成功と判断しないでください。不明瞭ならuncertain、失敗時は停止して操作者に返してください。
realのdry_runでは実測関節は動かず、把持成功と報告しないでください。
```

今回の実験では、このCodexセッションから `scripts/mcp_call.py` を介して実MCPの `tools/call` を実行し、返されたPNGを画像表示ツールで見て選択した。ブリッジは画像のbase64復号と転送だけを行い、色認識・置き場選択・LLM呼出しは行わない。ネイティブ接続のクライアントでは同じPNGを `ImageContent` として直接受け取る。stdioのプロトコル試験も実施した。

実験ログの自然言語と画像は実際の選択・確認記録。提出動画の説明字幕はログに基づく後編集であり、ChatGPTの画面録画やモデル内部の思考過程ではない。
