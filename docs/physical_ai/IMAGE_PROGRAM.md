# 画像からの位置推定と生成プログラム

> 既知高さ版・旧試行の記録。現在の未知高さ計測と段階XYZ生成は[STAGED.md](STAGED.md)、追加結果は[STAGED_RESULTS.md](STAGED_RESULTS.md)を参照。以下の未実装・未検証の記述は、この旧試行時点の範囲を示す。

## 何を推定し、何を既知としているか

| 値 | 現在の取得方法 |
|---|---|
| 対象の色・画像上の上面中心(u,v) | 接続先のCodexが実際のPNGを見て選択 |
| 作業台上の対象XY | (u,v)とカメラ校正、既知の高さ平面から計算 |
| 搬送計画で使う上面Z | **30mmという設定。prepare_pickは深度に合わせて軌道を変えない** |
| 未知の高さ | 通常構成では測定しない。旧仮想深度診断は実機共通構成から除外 |
| 対象の向き | 直立し面が作業台に平行という初期条件。姿勢推定なし |
| 把持高さ・接近高さ・持上げ高さ | sim専用の設定19 / 65 / 70mm（グリッパーフレーム） |
| 箱の場所 | 固定設定。箱の位置検出は未実装 |

同じピクセルには、カメラから伸びる一本の視線上の複数の3D位置が対応する。校正済み単眼画像だけから未知の高さまで一意には決まらない。本版は、その視線と「上面Z=30mm」の交点を使う。高さや物体姿勢が違えば位置推定と把持は保証されない。±3ピクセルの許容値は選択誤差の仮定で、画像認識器が推定した信頼区間ではない。

カメラの座標は+Xが右、+Yが上、前方が-Z。画像は左上原点、u右、v下。カメラ焦点距離fと姿勢R、位置Cから、視線は `R @ [(u-cx)/f, -(v-cy)/f, -1]`、その視線と高さ平面を交差させる。現行の主点は`((w-1)/2,(h-1)/2)`で、整数ピクセルは画素中心を表す。過去C01〜C04では`(w/2,h/2)`を使用し、その値と誤差は当時のログに保持する。実装は`so101_mcp/geometry.py`。カメラ仕様は[MuJoCo公式 Modeling](https://mujoco.readthedocs.io/en/3.17.0/modeling.html#cameras)を参照。prepare_pickの計算ではカメラ校正と既知高さを使い、追加したsample_depthでは同じ画像に整列した深度を使う。物体IDや真の物体位置はどちらにも使わない。

## 生成と実行

1. AIが日本語指示とPNGを読む。選択対象の上面中心と、見えている根拠を`prepare_pick`へ渡す。
2. サーバーがピクセル・画像鮮度・作業範囲を検査し、XYからIKと7段階の関節軌道を計算する。関節範囲、速度、軌道時間も検査する。一般の障害物回避計画は含まない。
3. 推定値・前提・関節軌道をJSON、MCP経由でその計画を実行するクライアントをPythonへ保存する。選択点を示したPNGも返す。
4. AIがプレビューとスクリプトを確認し、生成Pythonを実行するか、同じ`prepared_pick`をMCPで呼ぶ。
5. ローカル制御が凍結済みの計画を実行。生成スクリプトが完了後PNGを取得し、AIが画像を再確認して判定を記録する。

Python出力は決定的な雛形であり、AIは対象選択とパラメータ決定を担う。「LLMが毎回自由なプログラムを発明し、サーバーで任意コードを実行する」構成ではない。雛形のコード、生成したファイル、SHA-256、実行ログを収録する。各プログラムは元画像ID、ユーザー指示、ロボット世代に結び付ける。古い画像、観測後の動作、停止、別の指示を拒否する。`request_id`により通信再送時の二重動作を防ぐ。

## 実測と適用範囲

固定マーカーを消し、X=223〜257mm、Y=-100〜44mmの範囲から初期配置を連続値で生成した。2配置×2色の4試行で、AIが選んだピクセルからの搬送が4回成功。独立した初期シーン再現のPNGが実観測PNGと完全一致することを確認してから、XY誤差0.34〜0.77mmを計算した。対象の正解位置はこのオフライン評価だけで使い、選択・軌道生成への入力にはしない。

この誤差は理想的な校正と既知寸法を持つシミュレーションの4例に限る。実カメラの歪み、校正ずれ、未知高さ、遮蔽、傾き、混雑に対する性能は未検証。実機の`continuous_image_pick`はfalseで、`prepare_pick`は拒否する。既存の実機バックエンドは教示済み固定位置の動作を扱う。

## 深度による高さ測定を追加

2026-11-01の仮想深度診断は、現状の実機で取得できる入力と一致しないため通常構成から外した。[SENSORS.md](SENSORS.md)は履歴として保持する。現行の共通処理は実RGBの歪み補正・校正と既知平面への投影で、未知高さは測定したと扱わない。[RGB_REAL.md](RGB_REAL.md)を参照。

将来RGB-Dによる深度計測へ拡張する場合は、機器とドライバ、カメラ内部パラメータ・歪み、RGBへの深度整列、カメラからロボット基準への変換、作業台平面、時刻の対応、深度精度を実測する必要がある。現在の固定置き場・既知高さのRGB構成ではRGB-D機器を前提にしない。実機用の運動学・把持位置・指先オフセットは別に検証し、simの値をそのまま転用しない。
